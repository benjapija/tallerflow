# Biblioteca técnica del taller

Cada caso parte de una orden asignada o accesible por oficina, con una conclusión y una verificación confirmadas y vigentes del cuaderno. «Preparar caso para la biblioteca» abre el formulario técnico. No copia matrícula, VIN, contacto, documentos, importes ni fotografías. El texto libre exige revisión humana: el sistema no garantiza que quien lo redacta omita todos los datos personales.

«Biblioteca técnica» permite buscar por modelo, motor, síntoma, DTC o cualquier contenido técnico. El autor y oficina ven borradores y revisiones. Otros operarios reciben solo la versión publicada en su taller, sin referencias a la orden, autor, motivos privados o borradores.

Para publicar, una persona confirma por separado la revisión técnica y la ausencia de datos personales. Cada edición añade una versión; la última publicación sigue consultable durante un borrador nuevo. Una retirada conserva versiones y auditoría, y deja de compartir el caso. Una nueva versión confirmada puede volver a publicarlo.

Si la conclusión o verificación originales se corrigen o retiran, el caso publicado muestra «Necesita revisión». No se puede volver a validarlo con evidencia retirada. Un caso parecido es un antecedente, no una prueba de la causa actual; no autoriza trabajos, registra consumos ni cambia notas emitidas.

Los comandos pendientes se conservan cifrados y admiten reinicio. La publicación solo se confirma tras sincronizar. Conflictos de versión exigen revisar; reintentar la misma operación no crea otra versión. La copia completa versión 9 incluye casos, auditoría, recibos y cuadernos; admite restaurar copias anteriores 2–8. Auth conserva su recuperación independiente.

Validación: nueve Flutter específicos, once PostgreSQL locales, restauración entre bases independientes y doce SQL alojadas por cada proyecto Free. Los ensayos alojados se revirtieron, sin iniciar sesión real por Auth HTTP. Uso físico y Auth HTTP específico siguen pendientes. No necesita una API de IA ni servicios de pago.
