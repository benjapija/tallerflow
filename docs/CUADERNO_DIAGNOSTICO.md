# Cuaderno de diagnóstico

Cada orden conserva entradas de síntoma, hipótesis, comprobación, resultado, conclusión, intervención y verificación. Se anotan observación, condiciones, equipo y unidades, DTC y referencia documental consultada. No se deduce una causa a partir de un código ni se inventan especificaciones.

Operarios asignados y oficina pueden registrar observaciones. Conclusión y verificación requieren confirmación personal explícita. Una entrada no autoriza trabajo, suma tiempo ni consume piezas. La IA no participa en este registro.

Las entradas son acumulativas: una corrección referencia una entrada vigente y conserva el texto original. Una retirada añade motivo, fecha y persona. Un operario solo revisa sus entradas; oficina puede revisar las de otros. Las revisiones y retiradas exigen la última revisión de la orden. Mediciones independientes pueden sincronizarse sin sustituirse.

Puede añadirse evidencia técnica después de emitir la nota. Sus destinatario e importes siguen intactos. La nueva evidencia deja pendiente la comprobación final de la orden. La retirada de un dispositivo y los accesos caducados siguen el protocolo existente: no se restablece autoridad desde una copia.

Los registros sin conexión conservan sus identificadores después de reiniciar. Los reintentos de respuestas perdidas no duplican entradas. Copias y exportación de servidor incluyen cuaderno, operaciones originales y auditoría. La biblioteca de casos validados continúa pendiente; una observación del cuaderno no se publica automáticamente en una biblioteca.

Siete pruebas Flutter específicas, nueve PostgreSQL locales y ocho SQL alojadas por proyecto gratuito. Pruebas específicas de Auth HTTP y uso manual en equipos físicos pendientes. Las pruebas usan datos ficticios.
